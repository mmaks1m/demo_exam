## 1. Назначение и структура интерфейса

Настоящее руководство описывает регламент выполнения повседневных операций пользователями различных категорий (Гость, Покупатель/Клиент, Менеджер торгового зала, Администратор системы) в программном комплексе «ShoeShop».

Главное окно приложения спроектировано по принципу одностраничного каркаса с панелью инструментов и динамической заменой экранных областей:
- **Верхняя панель (Toolbar):** отображает текущего пользователя, его роль и кнопки навигации (*«Каталог»*, *«Заказы»*, *«Выход»*);
- **Рабочая область:** содержит карточки товаров, таблицу заказов либо форму редактирования;
- **Нижняя статусная панель:** информирует о количестве отображаемых записей, статусе подключения к базе данных и результатах фильтрации.

## 2. Авторизация и переключение ролей

При запуске комплекса отображается форма входа `LoginWindow`:

1. **Авторизованный вход:**
   - Введите логин в поле *«Логин»*;
   - Введите пароль в поле *«Пароль»* (символы маскируются);
   - Нажмите кнопку **«Войти в систему»** (или клавишу `Enter`).
2. **Гостевой доступ:**
   - Нажмите кнопку **«Войти как Гость»**;
   - Система откроет каталог с правами только для чтения (кнопки добавления в корзину и управления скрыты).

> [!NOTE]
> В случае трехкратного неверного ввода пароля система выводит предупреждающее уведомление о некорректных учетных данных.

## 3. Работа с каталогом товаров (ProductListWindow)

Окно каталога товаров является основным рабочим экраном для покупателей и персонала:

### 3.1. Структура карточки товара (ProductCardWidget)
Каждая позиция номенклатуры оформлена в виде отдельной визуальной карточки:
- **Миниатюра обуви:** загружается из каталога `resources/images/`. При отсутствии файла отображается заглушка-заполнитель;
- **Артикул и наименование:** официальный код изделия (`item_number`) и коммерческое наименование;
- **Категория и производитель:** бренд фабрики и тип обуви (мужская, женская, спортивная);
- **Ценообразование:**
  - Базовая цена (перечеркнута при наличии скидки);
  - Размер действующей скидки (выделен красным или контрастным цветом);
  - Конечная цена реализации со скидкой;
- **Складской остаток:** текущее количество пар в наличии на центральном складе магазина.

### 3.2. Поиск номенклатуры
- Введите часть названия, артикула или бренда в поле *«Поиск»*;
- Фильтрация выполняется в реальном времени с задержкой 300 мс для оптимизации нагрузки на базу данных;
- Для сброса поиска очистите поле ввода.

### 3.3. Фильтрация и сортировка
- **Сортировка по стоимости:**
  - *«По возрастанию цены»* — отображение позиций от бюджетных к премиальным;
  - *«По убыванию цены»* — отображение позиций от дорогих к бюджетным.
- **Фильтрация по скидкам:**
  - *Все скидки* (полный каталог);
  - *Скидка 0–9.99%*;
  - *Скидка 10–14.99%*;
  - *Скидка 15% и выше*.

## 4. Оформление заказа клиентом

Покупатель с ролью «Клиент» выполняет оформление покупки по следующему алгоритму:

1. Выберите нужную пару обуви в каталоге и нажмите кнопку **«В корзину»** (или кликните дважды по карточке товара);
2. В появившемся диалоге укажите требуемое количество пар (не более фактического складского остатка);
3. Перейдите в раздел **«Корзина / Оформление заказа»**;
4. Выберите предпочтительный пункт выдачи заказов (`pickup_points`) из раскрывающегося списка с адресами;
5. Проверьте итоговую стоимость корзины с учетом всех действующих акций;
6. Нажмите кнопку **«Сформировать заказ»**;
7. Запишите сгенерированный системой **3-значный код получения** (например, `712`) и ориентировочную дату прибытия товара.

## 5. Обработка заказов менеджером (OrderListWindow)

Сотрудник магазина с ролью «Менеджер» осуществляет операционный контроль торгового зала:

1. Перейдите во вкладку **«Список заказов»** на главной панели инструментов;
2. На экране отобразится таблица всех оформленных заказов покупателей:
   - Номер заказа (`order_number`);
   - ФИО клиента (`full_name`);
   - Дата создания и планируемая дата доставки;
   - Адрес выбранного пункта выдачи;
   - Суммарная стоимость;
   - Текущий статус заказа (*Новый*, *В обработке*, *Доставляется*, *Готов к выдаче*, *Завершен*).
3. **Изменение статуса заказа:**
   - Выделите заказ и нажмите кнопку **«Редактировать статус»**;
   - В открывшемся окне `OrderEditWindow` выберите новый этап обработки;
   - При необходимости скорректируйте дату доставки;
   - Нажмите кнопку **«Сохранить изменения»**.
4. **Выдача заказа покупателю:**
   - Клиент называет номер заказа и проверочный код получения;
   - Менеджер сверяет код в системе: при совпадении заказ переводится в статус *«Завершен»*, а остатки товара списываются со склада.

## 6. Администрирование номенклатуры (Роль «Администратор»)

Сотрудник с ролью «Администратор» обладает наивысшими полномочиями в системе:

### 6.1. Добавление новой позиции обуви
1. В окне каталога нажмите зеленую кнопку **«+ Добавить товар»**;
2. В форме `ProductEditWindow` заполните обязательные реквизиты:
   - *Артикул:* уникальный строковый идентификатор (до 20 символов);
   - *Наименование товара:* полное торговое название;
   - *Категория:* выбор из существующих категорий либо ввод новой;
   - *Поставщик и Производитель:* наименование фабрики/дистрибьютора;
   - *Стоимость:* базовая цена в рублях (целое неотрицательное число);
   - *Скидка:* процент скидки (от 0 до 99%);
   - *Количество на складе:* целочисленный остаток;
   - *Описание:* текстовые характеристики обуви (материал верха, подошва, сезонность);
3. Нажмите кнопку **«Выбрать изображение»** и укажите графический файл (`.jpg`, `.png`). Файл автоматически скопируется в рабочий каталог `resources/images/`;
4. Нажмите кнопку **«Сохранить товар»**. Запись мгновенно появится в базе данных.

### 6.2. Редактирование и удаление позиций
- Для изменения товара выделите карточку и нажмите кнопку **«Редактировать»**;
- Для удаления позиции нажмите кнопку **«Удалить»**.
  > [!WARNING]
  > Если товар уже входит в состав существующих заказов, прямое удаление блокируется внешним ключом СУБД для обеспечения ссылочной целостности (ГОСТ Р 56939-2024). В этом случае рекомендуется обнулить остаток на складе.
